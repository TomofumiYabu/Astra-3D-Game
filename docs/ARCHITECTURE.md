# 技術構成

## 採用技術

Node.js 24 / npm、TypeScript、Vite、Three.js / WebGL 2、Rapier 3D / WASM、Vitest、Playwright。Cloudで実装・物理検証・ブラウザー操作を行い、distを静的ホスティングへ配布する。DB・認証・実行時APIキーは不要。

依存はpackage-lock.jsonで固定する。再構築は `npm ci`。既存のCloud用Chromiumを検出し、他のイメージでは `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` を指定できる。

## モジュール

- `stages.ts`: 隊列ID、表示名、ヒント、標的位置。URLの入力は既知のIDへ解決する。
- `rules.ts`: チャージ・投擲速度・採点・結果。描画とDOMに依存しない。
- `physics.ts`: Rapierの剛体・イベントキュー・接触に基づく連鎖。状態と得点を所有し、描画へ姿勢を渡す。
- `models.ts`: おじさんとサイボーグの形状。サイボーグの静的部品は材質ごとに結合し、描画呼び出しを減らす。
- `scene.ts`: 環境反射、会場、照明、カメラ、パーティクル、キャラクターの描画上の姿勢。
- `audio.ts`: ユーザー操作後のWeb Audio合成。衝突音の発音頻度を制限する。
- `result-card.ts`: 3D描画のスナップショットへ結果を合成し、PNGをローカル保存する。Canvas・Blobのみを使い、外部サービスや追加依存は不要。
- `main.ts`: 入力、UI、リプレイの再生、localStorage、明示的なコピー操作。

## 物理と連鎖

固定ステップ1/60秒。1描画フレームで最大0.5秒分まで進める。描画間隔と物理時間を分離し、2/30/60fpsの呼び出しで同じ経過時間の結果を検証する。非有限値・負の経過時間は進めない。

得点対象のコライダーにCollision Eventsを設定する。おじさんまたは既に巻き込まれた敵との実接触と速度条件が成立したときに、対象を一度だけ活性化する。補助インパルス、得点、連鎖の深さ、描画用の衝突通知をこの時点で記録する。床との接触や接触していない対象には加点しない。

各リセットでWorldとEventQueueを解放して作り直し、接触履歴・得点・リプレイを空にする。静止中は時間を進めず、発射前に初期の敵を落ち着かせておく。

## リプレイ

2物理ステップごとに、全剛体の変換・得点・時刻をコピーして保存する。表示側は録画した変換を順に再生し、物理を再シミュレーションしない。上限8秒・18体なので記録量は一ラウンドに制限される。動画エンコード・ファイル出力はまだない。

## 描画と性能の境界

通常画質は影2048px、DPR最大1.5、アンチエイリアス有効。軽量画質は影512px、描画バッファの横幅最大800px。HTML UIの解像度は下げない。材質と物理ルールは共通。

静的都市はInstancedMesh、キャラクターの部品は材質単位の結合、火花は144個のプールで再利用する。Three.jsのRoomEnvironmentで反射を作り、外部HDRIを不要にする。

CloudのSwiftShaderは実WebGLコードの動作確認に使う。実GPUでのfpsやAAA品質を立証するものではない。Rapier compatのWASMを含むため、初回バンドルは約4.92MB（gzip約1.82MB）。サイズの最適化は残課題。
