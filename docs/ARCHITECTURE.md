# 技術構成と選定理由

## 採用

| 領域             | 技術                    | 理由                                                               |
| ---------------- | ----------------------- | ------------------------------------------------------------------ |
| 言語             | TypeScript / strict     | ゲーム状態・入力・物理と描画の境界を型で管理                       |
| 開発と配布       | Vite / npm / Node.js 24 | Cloud上で開発・ビルドし、静的ファイルとして配布可能                |
| 3D               | Three.js / WebGL 2      | ブラウザーでPBR材質・影・照明・カメラを直接制御                    |
| 物理             | Rapier 3D / WASM        | 剛体衝突を本物の物理エンジンで実行。Node側でも同じ実装をテスト可能 |
| UI               | HTML / CSS              | 操作・文字表示・アクセシビリティをゲーム描画から分離               |
| 単体・物理テスト | Vitest                  | 純粋なゲームルールと実Rapier世界の再現性を確認                     |
| 実操作テスト     | Playwright / Chromium   | CloudだけでWebGL・入力・結果表示を検証                             |

React等のUIフレームワークは、現段階の画面数では不要と判断。DB・クラウドAPI・秘密鍵も不要。依存バージョンはpackage-lock.jsonで固定する。

## 比較した候補

| 候補              | 適性                                  | 今回の判断                                                                                     |
| ----------------- | ------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Unreal Engine     | 高度な写実表現、充実した制作ツール    | 大規模SDK・GPUとエディター中心の制作、ブラウザー配布の制約から初回は不採用                     |
| Godot 4           | ゲーム機能が豊富。Cloudに実行環境あり | 有力だが、今回の短いブラウザー体験はTypeScriptでUI・操作テストまで統一する方が小さく始められる |
| Three.js + Rapier | 軽量なブラウザー配布、Cloudで自動検証 | 採用。高度な映像表現はアセットと演出を段階的に追加する必要がある                               |

## モジュール

- `src/game/rules.ts`: チャージ、方向、損害額、結果の文言。DOMや描画に依存しない。
- `src/game/physics.ts`: Rapier初期化・剛体・1/60秒固定ステップ・衝突後の移動判定・リセット。
- `src/game/scene.ts`: ロビー・荷物・材質・照明・カメラ・狙いのガイド・描画。
- `src/game/audio.ts`: ユーザー操作後に合成する簡易効果音。
- `src/main.ts`: UI、キーボード／ポインター入力、スコア、状態の連携。

物理を60Hzで更新し、描画フレームごとに剛体の変換を反映する。1フレームの物理進行を0.1秒に制限し、復帰時の暴走を防ぐ。入力の時間はperformance.nowで測り、物理には角度と威力だけを渡す。

## 品質と性能の境界

Cloudのテスト描画はSwiftShaderによるソフトウェアレンダリング。これは実際のWebGLコードの確認であり、実GPUで60fpsを出せる根拠にはならない。通常描画は影2048px・DPR最大1.5。`?quality=low` は影512px・DPR1・アンチエイリアスなし。どちらも同じ物理・ルールを使う。

RapierのcompatパッケージはWASMを含むため初回バンドルが大きくなる。初回は読み込み中表示で対応し、サイズ最適化・WASM分離・圧縮配信は次段階に残す。
