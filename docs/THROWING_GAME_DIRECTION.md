# 改善案 — ありえない物を投げる破壊コメディ

更新日: 2026-10-16（日本時間）。状態: 方針が承認され、おじさん×サイボーグ、3隊列、連鎖得点、カメラとネクタイ演出、リプレイ、お題URLのコピーを実装。現行動作は [仕様](SPEC.md) を参照。戦車・怪獣・ケーキ・追加アクションなどは引き続き拡張計画。

## 今回の方針

遊びの中心を「ありえない物を自分で投げ、大きな連鎖で吹き飛ばす爽快感とシュールさ」に置く。ホテル・旅行者・荷物はステージの題材の一つとして扱う。仮題は **『それ、投げるんですか？』**。正式な作品名とリポジトリ名の変更はまだ行わない。

前回の企画比較は「壊さず運ぶ」を強く推したが、これは一部のお題として取り込める。今回の主軸は、気軽な一投でも気持ちよく、工夫した一投ならさらに派手になるゲーム。最大威力を選んだだけで失敗させる設計や、常に慎重な運搬を求める設計を共通ルールにはしない。

「巨大化して猫を救う」案は独立プロジェクトへ切り出す。[引継ぎ書](ONE_GIANT_RESCUE_HANDOFF.md) を参照。

## 一つのゲームとしてのまとまり

ステージごとに **投げる物 × 吹き飛ばす相手 × 物理的な特性** を変える。共通するのは、狙う → ためる → 投げる → 衝突と連鎖を見届ける → 即再挑戦、という操作と時間感覚。

世界観は「異常な投擲を大真面目に採点するショー」。実況・画面・材質は重厚にし、投げる対象の意味不明さを引き立てる。各ステージの説明は「本日の投擲物：おじさん」「戦車を投げて怪獣を倒せ」の一行で伝わる形を目指す。長い設定説明を前提にしない。

最初の一投から当てやすい標的配置を作り、角度・入射位置・回転の違いで連鎖の形を変える。全倒しした後にも、遠くまで飛ばす、別経路へつなぐ、特定の二体を同時に巻き込む、といった次の工夫を残す。

## 共通ループ

1. 0〜3秒: 投げる物と相手の異常な組み合わせを同じ画面に見せる。主役がUIに隠れない構図にする。
2. 3〜6秒: 狙いを変え、長押しして離す。初期照準と標準の投擲でも見せ場が出る。
3. 6〜9秒: 最初の衝突。飛んでいる軌道を追い、衝突点が分かる距離で見せる。
4. 9〜15秒: 吹き飛んだ敵や小物が次の対象へ衝突し、二段階以上の連鎖になる。
5. 15〜20秒: 決めの落下や意外な着地を見せ、結果と再挑戦へ移る。物理が止まる前に結果画面で隠さない。

秒数は試作の目標。長い待ち時間を固定せず、主要な連鎖の終了と上限時間から結果表示を決める。

初期操作は左右の狙いとチャージを維持する。高さや回転の調整、飛行中に一回だけ使える追加アクションは、通常の一投で爽快感を確認した後の拡張候補。追加アクションの例は、おじさんの大回転、戦車の追加加速、ケーキの空中分離。最初から多数の操作を要求しない。

最初の実装候補は **おじさん × サイボーグ**。ユーザーが挙げた組み合わせの異常さが伝わりやすく、衝突の気持ちよさも一つの広場で評価できる。次に重さの違いが出る戦車、第三段階で分離挙動のケーキを作る。五ステージを同時に作る計画ではない。

## ケーキ案の取り込み方

独立作品にする必要はない。前回案の「壊れそうな豪華な物」「式場の緊張感」「助かった後に別の段が落ちる」を一ステージに利用できる。

共通操作に合わせるなら「台車で最後まで運転する」を **ケーキを空輸し、指定台へ着地させる** に変える。通常のお題では、飛び散る段で装飾を巻き込む爽快感を主役にする。追加のお題で「人形だけを届ける」「できるだけ形を残す」を用意すれば、慎重さも遊びの幅として残せる。

前回の台車操作をそのまま使う場合は、幕間の別操作のミニゲームになる。共通の投擲が十分に面白くなった後の拡張として検討する。

## 爽快感を作る具体策

### 衝突の読みやすさと手応え

- ため中に主役の姿勢、地面の小石、低い効果音を変え、放す瞬間へ期待を集める。
- 初撃に短いヒットストップ、衝突方向への小さなカメラ反応、低音・金属音・遅れて来る落下音を重ねる。目安40〜80ms程度から調整し、毎接触では発生させない。
- 最初の衝突点と飛ぶ方向が見える構図を優先する。粉じんや破片が主役を隠さないようにする。
- サイボーグの群れは、先頭が跳ね上がる、後列へ連鎖する、重い一体が最後に倒れる、と時間差をつける。
- 画面揺れ軽減と音量操作を維持する。音を使わなくても衝突と連鎖が伝わることを確認する。

### 物理と演出の担当を分ける

主役・敵・得点対象は実際の剛体と接触で動かす。小さな火花・装甲片・粉じんは、数を制限した視覚効果として扱える。描画負荷を増やすために、すべての破片を独立した物理オブジェクトにしない。

見える接触を起点に、外向き・上向きへの補助インパルスなどを調整する。ルールは一貫させ、実際には当たっていない敵まで無関係に飛ばす演出に頼らない。見た目は写実的でも、飛距離と重力感は爽快感に合わせて調整できる。

おじさんは初期試作では単純なコライダーと姿勢変化で始め、必要な関節だけ増やす。全員を精密なラグドールにすることを先行条件にしない。戦車・怪獣・大きい敵は別の質量感が伝わるようにし、見た目だけを置き換えた同じ箱にしない。

### 一発ネタを繰り返したくなる仕組み

- 「吹き飛ばした数」に加え、連鎖・飛距離・場外への落下・特別な巻き込みを評価する。上限個数だけで得点が頭打ちにならないようにする。
- 初見では細かな採点式を読ませず、飛んだ瞬間に短い表示で褒める。詳細は結果画面で確認できるようにする。
- 主役が直接当たった一撃と、二次衝突による連鎖を区別する。重複接触で点数が増え続けない判定にする。
- 道具を増やすときは、重い・跳ねる・分裂する・滑る・回転するといった操作結果の差を追加する。
- 固定のお題コードとリプレイで「同じ配置を別の投げ方で」を支える。初期の配布にバックエンドやオンラインランキングを必須にしない。

## 実装の進め方と現在地

ホテル試作から、おじさんと18体のサイボーグへ移行済み。`stages.ts` に3隊列、`rules.ts` に連鎖・飛距離の採点、`models.ts` に人物と敵を分離した。下記1〜2と、3の初期演出・記録リプレイまで実装済み。次のステージでは質量・形状・カメラなど、必要になった共通項を抽出する。

1. **一つの衝突を完成させる。** 小さな広場、主役1体、サイボーグ12〜20体程度。発射・初撃・二次衝突・結果・再挑戦を作る。
2. **入力の工夫を結果へつなぐ。** 正面なら列を貫く、横からなら別の集団へ跳ねる、と少なくとも三つの異なる結果を作る。
3. **見せ方を磨く。** 主役のシルエット、質感、光、低音、落下の間、カメラを整える。キャラクター素材は出典・ライセンスを記録する。
4. **二つ目の物理特性を追加する。** 戦車の重い押し込みを作り、同じ操作で異なる気持ちよさが出るかを確認する。
5. **ケーキの分離とお題を加える。** 成果が出た後に、他の投擲物とリプレイへ拡張する。

## 検証と判断

Cloudでは、フレームレートに依存しない固定ステップ、実衝突による得点、二次連鎖、リセット、物理値の発散防止、実WebGL描画、キーボード・ポインター操作を検証する。新しい得点・ステージの仕様に合わせてテストを変更する。

プロトタイプは、正面への一投で16体撃破・13連鎖を確認。3隊列×3角度の物理テストで少なくとも三種類の結果と安定性を検証済み。無音の短い動画で「何を投げて何を倒したか」が分かるか、着地まで見たくなるか、別の投げ方を試したいかは人の反応で評価する。新ステージの人による試遊評価は未実施。

質感の向上だけで拡散を予測しない。シルエット・スケール・因果が見えるカメラ・一投の操作感を優先し、広大なマップや大量のアセットを作る前に見せ場を確認する。
