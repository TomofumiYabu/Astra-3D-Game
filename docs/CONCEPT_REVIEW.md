# 企画再検討 — 配信と短い動画の見せ場

作成日: 2026-10-16（日本時間）。対象: 公開済みプロトタイプ、コード確認時点 `e0408f9`。

本書は現案の改善案と代替案の比較。採用決定や実装済み仕様ではない。ユーザーの依頼に基づき、主担当が現案を分析し、3人のサブエージェントが別方向の企画を独立検討した。

**後続の方針更新:** ユーザーの追加指示により、ケーキは一つのステージとして扱い、ありえない物を投げる爽快感・シュールさを本作の中心に再検討する。最新案は [投擲ゲームの改善方針](THROWING_GAME_DIRECTION.md)。以下の配送版・ケーキ独立案の優先順位は更新前の検討記録。巨大化救出案は [独立企画の引継ぎ書](ONE_GIANT_RESCUE_HANDOFF.md) へ切り出した。

## 判断

現案は、ホテルの世界観・軽い操作・短いラウンドという制作基盤ができている。一方、現状の「荷物を投げて荷物を倒す」だけでは、二本目の動画を見る理由や、自分で違う結果を試す理由が弱い。映像制作を増やす前に、目的・危機・選択・結果の関係を検証したい。

優先候補は **『失礼します、ケーキ通ります。』**。壊したくない対象が一目で分かり、操作中に危機を回避する余地があり、既存ホテルの資産も利用できる。比較対象は現案を改めた **『絶対に壊さず、お届けします。』**。新奇性を重視する次候補は **『猫を降ろすだけ。』**。支柱撤去案は、支えの読みやすさと物理安定性の難度が高いため、その次とする。

これは設計上の仮説であり、SNSでの拡散や売上の予測ではない。短尺動画での理解しやすさと、長時間配信を支える内容量も別々に検証する。

## 確認できたことと調査の限界

- `docs/SPEC.md`、描画・入力・得点・物理実装、公開サイトの通常画質スクリーンショットを確認した。
- 現行物理で角度9通り × 威力5通りの計45入力を試した。角度は -22/-16/-10/-4/0/4/10/16/22度、威力は0.15/0.35/0.55/0.75/1。各試行は初期化後、1/60秒刻みで結果まで進めた。
- 初期角度0度＋最大威力で10個すべて倒せた。0度の他の威力では6/9/9/9個。9方向中5方向は、調べた威力5段階を変えても倒した個数が同じだった。入力探索の結果は `artifacts/concept-input-sweep.json` に保存した生成物で、Git管理には含めない。
- この45入力は遊びの選択肢を調べる実験。全入力の網羅、プレイヤーの楽しさ、視聴者の反応を測ったものではない。
- サブエージェントはSteamの商品ページ・APIと開発元の公式サイトを取得しようとしたが、CloudのプロキシがCONNECT 403を返した。公式本文、現在の販売本数、配信視聴数、SNS再生数の確認はできていない。
- 末尾の外部リンクは比較候補。各作品についての一般的な既知情報は、今回取得して裏付けた市場調査と区別する。未実施のユーザーテストを実施済みと扱わない。

## 現案を続ける場合

### 弱点

1. 初期方向で最大までためれば満点になり、次に変えたい操作が見つかりにくい。
2. 壊すこと自体が正解なので、「大切なものが危ない」「助かった」という感情の振れ幅が小さい。
3. 見えるのは荷物同士の衝突で、ベル係の仕事や客の期待は主に文章の中にある。
4. 固定配置・同種の標的・固定された得点上限のため、結果の違いが個数に集約される。
5. 通常画面では荷物がロビーに対して小さく、「巨大な物を扱う」という約束が映像に十分表れていない。装飾的なUIが画面の広い範囲を占めるため、縦長の動画への切り抜きも難しい。

### 改善の優先順位

**最優先: 『絶対に壊さず、お届けします。』へ目的を変える。** 巨大な荷物を、ロビー反対側の指定された受取台へ運ぶ。荷物の到着と無傷率を主な成功条件にし、損害額は事故の記録として見せる。最大威力は飛び越え、弱すぎると届かず、角度と力を調整する理由を作る。安全な直線経路と、家具を利用する危険な近道を見せる。

**次に: 一つの強い荷物と、因果が読める二段階の事故を作る。** 初期試作はドア幅ほどある旅行鞄と、受取台・回転扉など少数の道具に絞る。後からグランドピアノや巨大な壊れ物へ広げる。「扉に当たる → 向きが変わる → 到着寸前に台車が動く」のように、観客が先を予想できる配置にする。入力に関係なく再生される爆発や、ランダムな即失敗は主役にしない。

**続いて: 15〜20秒の中に、目的・危機・一度の救い・結果を置く。** 発射前に行き先と障害物を同じ画面へ入れ、衝突時だけ短く寄る。最後まで「荷物がどこへ届くか」を見せてから事故報告を出す。成功寸前と大失敗の両方が見どころになる構図を作る。スローモーションや音は因果を読みやすくするために使う。

**最後に: 他人が同じお題を試せるようにする。** 荷物・配置・目標を固定したお題コードやURLを用意する。同じ配置でも操作を変えると結果が変わることを先に確認する。配置の共有は、異なるブラウザー間の物理完全一致や不正対策付きランキングを保証しない。リプレイは記録した変換を再生する方式を検討し、動画書き出しは基本ループの評価後に追加する。

改善版の短い動画例: 「こちらを、傷一つなく」→ ドアほど大きい鞄 → 弱めに投げて扉を通過 → 受取台の縁に引っ掛かる → 一度持ち直してから台車ごと走り出す → 配送成功、ロビーは惨事。

グラフィックは主役の荷物・床・反射・照明・カメラ距離に集中する。高品質なアセットを増やす前に、この一場面が粗いモデルでも伝わるかを試す。

## 代替案1: 失礼します、ケーキ通ります。

**一言:** 結婚式で、人の背丈を超えるウェディングケーキを台車で届ける20秒。

- 最初の絵: 傾いた7段ケーキ、奥に式場と新郎新婦のシルエット。「ご入刀まで20秒」。目的と壊したくない理由を一画面に入れる。
- 操作: 台車の速度・進行方向を制御し、一回だけケーキを支えられる。曲がる・止まる・助ける判断が到着まで続く。
- 動画: 近道で加速 → 段差で上段が傾く → 支えて助かる → 急停止で別の段が落ちる → 頂上の人形だけが先に到着。「7段中2段、お届けしました」。
- 再挑戦: 減速位置を変える、近道を使わない、支えを最後まで温存する。上手に救えた成功も見せ場にする。
- 現案より強いと考える理由: 視聴者が失敗してほしくない対象を即座に理解でき、事故がプレイヤーの判断と結びつく。配信者に「止まって」「今支えて」と言いたくなる余地がある。
- 実装範囲: 一つの会場、一つの短いコース、ケーキ7段と台車。既存ロビーの材質・照明・物理を再利用する。初期はクリームの連続変形、流体、大勢の人物の動作を作らない。
- 弱点: 難しいだけの操作は苛立ちになる。ケーキが硬い円柱の積み木にしか見えないと魅力が薄い。崩れ方と一度助けられる操作の調整が重要。
- 最初の検証: 穏やかな運転では到着し、急停止では操作に応じて崩れ、適切な支え操作なら救える一コース。

## 代替案2: 猫を降ろすだけ。— 巨大化は一回だけ

**一言:** 屋上の猫を助けるため、街の物を一つだけ巨大化する。

- 最初の絵: 屋上の小さな猫と路上の脚立。プレイヤーが脚立をビルほどに伸ばす。「その助け方はおかしい」と一目で伝わる落差を狙う。
- 操作: 脚立・傘・マットなどから一つ選び、向きと大きさを決める。対象ごとに救出方法と副作用を設計する。
- 動画: 巨大脚立が橋になる → 看板に引っ掛かる → 街の物を押しながら倒れる → 猫はクッションへ、街は大惨事。
- 再挑戦: 別の道具、巨大化の量、倒す向きを試す。「最少被害の救出」と「最も雑な救出」の両方をお題にできる。
- 現案より強いと考える理由: 応援する対象と、実行前に口を出せる選択肢がある。巨大化の瞬間自体も短い動画の見せ場になる。
- 実装範囲: 一街区、猫一体、初期は脚立一種類、動く物は数十個程度。都市全体の破壊を作らない。ミニチュア特撮のような画角と材質に絞る。
- 弱点: 猫・道具・救出先を同時に見せる構図が難しい。巨大化中のコライダー変更は物理が不安定になりやすい。猫の危機が不快さにつながらないよう、負傷表現を避けた結果を設計する。
- 最初の検証: 脚立の向き・大きさの違いで、救出の成否や周辺被害が読める形で変わる一場面。

## 代替案3: そこ抜くんですか？— 地上300mの解体バイト

**一言:** 高層ホテルを倒さず、指定された支柱だけを引き抜く。

- 最初の絵: 数本の梁に支えられた豪華なペントハウス。細い一本が赤く光り、監督から「その柱、もう要りません」。
- 操作: 補助ジャッキを一つ配置し、指定の梁をつかんで引く。止める・放す・押し戻すことで傾きを救える。
- 動画: 梁が抜ける → 上階が傾く → 慌てて押し戻し助かる → 反対側の大きな浴槽が滑る。「あと12cmで退勤だった」。
- 再挑戦: 補助を置く位置、引く方向、途中で止める位置を変える。乱数による事故より、接触と重心の因果を見せる。
- 現案より強いと考える理由: 観客が事故を予想して待てる時間と、プレイヤーが危機を救う時間がある。
- 実装範囲: 一区画、梁3本、補助1個から始める。発展後も20〜40個程度の大きな剛体で表現し、都市は背景、監督は字幕と無線音にする。
- 弱点: 何が建物を支えているか分からなければ、地味で理不尽なパズルになる。毎回即全壊しても弱い。支持と引き抜きの物理調整が三案の中で特に難しい。
- 最初の検証: 危険な支柱が映像で読み取れ、途中の救済が実際に成功し、慎重な撤去と大崩落の両方が成立する一場面。

## 比較

以下は現在の資産と設計に基づく定性的な判断。市場調査の点数ではない。

| 案             | 見せ場の核                     | プレイヤーが変えること     | 制作上の大きな課題       | 優先判断               |
| -------------- | ------------------------------ | -------------------------- | ------------------------ | ---------------------- |
| 現案の配送版   | 丁寧な仕事と大惨事の落差       | 角度・力・配送経路         | 発射後にも期待が続く配置 | 既存案の比較用試作     |
| 巨大ケーキ     | 壊したくない、今なら助けられる | 速度・曲がり方・支える時機 | 読める揺れと救済操作     | 第一候補               |
| 巨大化で猫救出 | 助け方の異常さとスケール変化   | 道具・大きさ・向き         | 巨大化の物理と構図       | 新奇性を重視する次候補 |
| 高層の支柱撤去 | 抜く怖さと遅れて来る崩壊       | 支えの位置・引き方         | 支持構造の可読性と安定性 | 検証難度が高い候補     |

どの案も当面は一人用・静的配信・Three.js/Rapierを維持できる。多人プレイ、視聴者によるリアルタイム介入、オンラインランキングを必須条件にしない。Cloudでは操作と物理を検証できるが、実GPU性能や面白さは自動テストの合格だけでは分からない。

## 次の検証案

1. 追加アートに入る前に、現案の配送版とケーキ案の短い一場面を比較する。最初から三作品を並行して完成させる必要はない。
2. どちらも「成功」「失敗寸前から救う」「大失敗」が、入力に対応して起きるかをCloudで確認する。入力を変えても同じ落ち方になる場合は構造を見直す。
3. 未見の5人程度へ、無音の3秒映像と15〜20秒映像を見せる。仮の足切り基準は、4人が目的・危険を説明でき、3人が事故の理由と次に変えたい操作を言えること。数値は今回の検証用の仮置きで、業界標準でもバズの予測でもない。
4. プレイでは説明せずに再挑戦するか、異なる操作を試すかを見る。人への依頼・配布・反応の収集はまだ実施していない。
5. 通過した案で主役の材質・光・カメラ・効果音を磨き、複数のお題とリプレイへ進む。その後に、許可された公開テストで実際の視聴維持や再挑戦を評価する。

短尺の分かりやすさが通過しても、長時間配信には複数のお題・難度・操作の上達が必要。SNSでの拡散は、投稿の仕方、視聴者層、配信者との相性にも左右される。
